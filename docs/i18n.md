# i18n Module (English / German)

### Overview

The whole site can be switched between English (the default for first-time visitors) and German. `src/i18n/` is an in-house runtime with typed TypeScript dictionaries and no npm dependency. English messages are the source of truth. A German dictionary that is missing a key, has an extra key, or renames a placeholder or tag fails `tsc`. Pokémon, move, item, ability, type, nature and stat **names** are not part of this module: they come from `src/lib/pkmn/i18n` (see [PKMN](./pkmn.md)), which reads the data locale from here.

Design of record: this page (the original i18n design spec is maintainer-only; not in this repo). Canonical decisions: [spec §17](./poketools-spec.md#17-internationalization-deen). Agent rules: [`AGENTS.md`](../AGENTS.md) "Text goes through `src/i18n`" and the `## i18n` sections of the nested `src/{app,components,lib}/AGENTS.md`.

Decisions in short:

| # | Decision |
|---|---|
| D1 | Locales `en` (default) and `de`. No `Accept-Language` negotiation, no URL prefix, no `[locale]` segment. |
| D2 | No i18n library: typed dictionaries, `de` checked against `en` at compile time. |
| D3 | Client components statically import the namespace modules they use (both languages per module). The provider carries only `locale`, `dataLocale`, `timeZone` and `requestTime`. |
| D4 | Three cookies, one year, `Path=/`, `SameSite=Lax`, `Secure` in production, not `httpOnly`: `plc_locale` (`en`\|`de`), `plc_pkmn_lang` (`en`, or absent = follow the UI language), `plc_tz` (IANA zone written by the browser). |
| D5 | `getLocale()` / `getDataLocale()` / `getTimeZone()` are React `cache()` wrappers over `cookies()`. They never run inside `unstable_cache` / `cachedRead`; cached values never hold localized text and no cache is keyed by locale. |
| D6 | The root layout reads the locale cookie, so every route renders dynamically. Accepted. |
| D7 | A language switch is `POST /api/locale`, then `router.refresh()` (or `location.reload()` on a 3D route-world page). |
| D8 | API errors keep the English `error` and add `code` plus optional `params`; clients translate the code. |
| D9 | Times are stored in UTC and shown in the viewer's browser zone (hydration-safe). Formats: `en-GB` and `de-DE`, 24-hour clock in both. Deadlines may also show `Europe/Berlin` league time. |
| D10 | Viewerless text uses `seasons.language` (default `'de'`); overlays use `?lang=` first, then the league language, never the cookie. |
| D11 | Worlds follow the viewer. Themes carry no language (`RouteThemeDefinition.locale` is deprecated); painters get the viewer locale before textures are built. |
| D12 | German style: casual *du*; English messages copy today's English literals verbatim. |
| D13 | Hooks never throw without a provider: they render English and warn once outside production. |
| D14 | i18n owns the whole Pokémon-terms seam: one cookie (`plc_pkmn_lang`), one writer, one provider, one control (`LanguageOptions`). |
| D15 | EPB list prose (`rationale`, `special_rules_text`, `historical_data`) stays German with `lang="de"` in English mode; there are no stored English copies. |

### Core Functions/Classes

**Namespaces.** A namespace is one directory under `src/i18n/messages/`:

```
messages/<ns-path>/en.ts     export default { … } as const;                  (source of truth)
messages/<ns-path>/de.ts     export default defineDe<typeof en>()({ … });
messages/<ns-path>/index.ts  export const <camelName>Messages = defineNamespace('<ns-path>', en, de);
```

- The directory path is the namespace id (`draft/screen`); the export is the camel-cased path plus `Messages` (`draftScreenMessages`). Error catalogs export `errors<Domain>` (`errorsCommon`, `errorsDraft`).
- There is no registry, no `<Messages>` scope component and no string-named lookup: a component imports the namespace object. Adding a namespace never edits a shared file.
- A namespace imported by client components holds at most about 250 keys; split larger ones by screen.
- Leaves are strings (`{name}` placeholders; paired `<tag>…</tag>` rich tags; no literal `{ } < >`) or plural objects `{ zero?, one, other }` with an implicit `count`. Groups nest up to three levels and never use the keys `zero`/`one`/`other`.
- Keys are camelCase, except maps keyed by a code or enum value, which use the value verbatim (`LINE_TAKEN`, `matchStatus.pending_confirmation`, `utility.hazard_setting`). Only `[A-Za-z0-9_]` is allowed.
- Every message is a whole sentence or label in sentence case. Never concatenate fragments. ALL-CAPS designs render with CSS `uppercase` or `upperForPaint(text, locale)` (`ß` becomes `SS`).

**Shared namespaces** (filled by the core, read-only for everyone else): `common`, `nav`, `meta`, `language`, `enums` (every DB enum plus price groups and bracket sides), `glossary` (league vocabulary, §Glossary), `content` (engine-label templates), `time` (relative and countdown phrasing). Error catalogs live under `messages/errors/<domain>`; their registry (`ApiErrorCode`, the catalog list) is `src/i18n/messages/errors.ts`, beside the folder rather than an `errors/index.ts`, because every `messages/**/index.ts` is one namespace.

**Format-pack prose.** League rule prose that is tuning (token rules, the participation line, price-group labels, the stage-lock and line-rule texts) lives in the active [format pack](./format-packs.md#messages)'s `messages`, not in the namespace files. The namespace keeps its id and key paths and spreads the pack's subtree into the group that holds those leaves, so consumers do not change:

```ts
// src/i18n/messages/world/evoliga/en.ts
import { formatPack } from '@/lib/format-pack';
const P = formatPack.messages.en.worldEvoliga;
export default { …, rules: { heading: 'Rules', …, ...P.rules } } as const;
// de.ts
const P = formatPack.messages.de.worldEvoliga;
export default defineDe<typeof en>()({ …, rules: { heading: 'Regeln', …, ...P.rules } });
```

- `defineDe` still checks the namespace: `typeof en` carries the pack leaves with their literal types, and the German side spreads the pack's German subtree.
- The example pack's `messages/en.ts` is the contract for every pack: a pack's English tree is declared with `definePackEn<typeof ExampleEn>()({ … } as const)` (`src/lib/format-pack/define.ts`), which applies the `defineDe` rules (keys, placeholders, tags, plural shapes) and lets the texts differ.
- Utility-category labels are not spliced: they are the pack's `messages.<locale>.utility` map, read with `utilityLabel(key, locale)` from `@/lib/format-pack`.
- Pack files are allowlisted for the hard-coded string check (`src/format-packs/**` in `scripts/i18n-allowlist.json`); `src/lib/format-pack/__tests__/pack-contract.test.ts` checks their en/de keys instead.

**Owned namespaces with wide readers:** `pkmn` (`src/i18n/messages/pkmn`, owner PK-2) holds the shared Pokémon-data UI text: the type-icon `aria-label`, the "EN" fallback tag and title on a description without German game text, the PokéAPI attribution and the damage-calc KO phrasing (`guaranteed {ko}`, `{percent} chance to {ko}`). Pokémon, move, item, ability and type names are never in it; they come from `src/lib/pkmn/i18n`.

**Failed checks in `tsc`.** A German dictionary that breaks the contract reports on the offending key as `I18nCheckError<'…'>` (`types.ts`), with the reason in the literal: `'unknown key'`, `'unknown placeholder'`, `'expected a string'`, `'expected a plural object'`, `'plural forms are zero, one and other'`, `` `placeholders must be: …` `` or `` `tags must be: …` ``. Read the message inside the brand, not the surrounding assignability text.

**Translator** (`core.ts`):
- `t(key, params?)`: typed key and params; number params are formatted per locale (`formatParamNumber` in `intl-cache.ts`) with `useGrouping: 'min2'`, so grouping starts at five digits: a year or a four-digit count prints as `2026` (never `2,026` / `2.026`), `12345.5` as `12,345.5` / `12.345,5`.
- `t.rich(key, { tag: (chunks) => … })`: rich messages; unknown tags render as text.
- `t.dynamic(key, params?, fallback?)`: runtime keys (enum values, codes). A missing leaf falls back to English, then `fallback`, then the key, and warns outside production.
- `createTranslator(ns, locale)` is pure and client-safe: use it for viewerless text and in pure functions that take a `locale`.

**Server** (`server.ts`, `import 'server-only'`): `getLocale()`, `getDataLocale()`, `getTimeZone()` (React `cache()`), `getT(ns, locale?)`, `getMessagesFor(ns, locale?)`, `getFormatter(opts?)`, `getI18nProviderProps()` for the root layout and nested providers, and `getRequestLocale(req)` / `getRequestDataLocale(req)` for route handlers (they parse the `Cookie` header).

**Client** (`client.tsx`): `I18nProvider` (mounted once, outermost, in `src/app/layout.tsx`), `useLocale()`, `useDataLocale()`, `useT(ns)`, `useMessages(ns)`, `useFormatter()`, `useTimeZone()`, `useRequestTime()`. Without a provider no hook throws: `useLocale`/`useDataLocale` return `'en'`, the zone is `Europe/Berlin`, and `useT` warns once outside production. Nested providers are intended (broadcast overlays, social-image capture in the league language).

**Formatting** (`format.ts`, `LocalTime.tsx`). `Formatter` offers `number`, `percent`, `percentOf`, `instant(value, preset)`, `calendarDate(day)`, `relative`, `list`, `clock(seconds)` (`2:30`, `12:05:09`), `duration(seconds)` (`12h 5m` / `12 Std. 5 Min.`) and `zoneLabel`. Presets:

| Preset | `en-GB` | `de-DE` |
|---|---|---|
| `date` | 9 Oct 2026 | 9. Okt. 2026 |
| `dateLong` | 9 October 2026 | 9. Oktober 2026 |
| `dateShort` | 09/10/2026 | 09.10.2026 |
| `dateTime` | 9 Oct, 18:30 | 9. Okt., 18:30 |
| `dateTimeYear` | 9 Oct 2026, 18:30 | 9. Okt. 2026, 18:30 |
| `weekdayDateTime` | Fri 9 Oct, 18:30 | Fr., 9. Okt., 18:30 |
| `time` | 18:30 | 18:30 |
| `monthYear` | October 2026 | Oktober 2026 |

Time-zone rules (hydration safety):
1. Client components format instants only through `useFormatter()`; the server snapshot and hydration use the provider zone (the `plc_tz` cookie, else `Europe/Berlin`), then React re-renders once in the browser zone.
2. Server components never format an instant with a time of day: they render `<LocalTime value={iso} preset="dateTime" />`. A pure calendar date may use `formatter.calendarDate()` on the server.
3. `TimeZoneSync` (inside the provider) writes `plc_tz` after mount; it never refreshes the page.
4. Relative times use `<RelativeTime>`; a value derived from "now" (an overdue flag) reads `useMinuteClock()`; `Date.now()` is never read during render anywhere else.
5. Canvas and 3D painters run after mount and may build a formatter with the browser zone directly.
6. Deadlines render `<LocalTime preset="weekdayDateTime" zone="both">`, which appends the league time (`LEAGUE_TIME_ZONE`, `Europe/Berlin`) when the viewer's zone differs.

The old `src/lib/utils/date.ts` helpers are gone: every call site moved to the formatter and the sweep deleted the file.

**Content helpers** (`content/`):
- `translateEngineLabel(kind, text, locale)`: DB-stored English engine names (round, slot, group, bracket names, notes, the "System" actor) are translated at display time by pattern; non-matching text (an admin's own names) is returned unchanged. Writers are not changed.
- `enumLabel(t, group, value)`: labels from `enumMessages`; an unknown DB value renders raw. A new value of a labelled DB enum fails `tsc` until it is labelled.
- `draftPoolFormatText(t, pool)`: a draft pool's turn order and pricing as one label ("Snake · Fixed costs") from `draft/legacy/board` `poolFormat`; queue-engine pools read "Snake · Point buy". The `draft_completed` Discord embed localizes the same pair from `outbound/discord` (`draftCompleted.order` / `.pricing`, payload `pool_format`).
- `achievementText(def, locale)`: catalog name and description by achievement key, else the DB text.
- `leagueProse(text)`: German league prose (EPB rationale, historical data) is always German; the caller sets `lang="de"` on its element. Special-rule text uses the draft module's `specialRulesTextFor(entry, locale)`.

### Data Flows

**Language switch.** `LanguageOptions` (two radios, English / Deutsch, each written in its own language, and the "Keep Pokémon terms in English" checkbox, visible only while Deutsch is selected) is the only control. It is rendered by the NavBar picker (`LanguagePicker`, before the palette picker), the mobile drawer section (`LanguagePickerSection`) and the settings page card (`LanguageSettingsSection`, a client export that the server page `src/app/(player)/dashboard/settings/page.tsx` renders). It calls `applyLanguagePreference({ locale?, pkmnTerms? }, router)`, which:
1. posts to `POST /api/locale`;
2. sets `document.documentElement.lang` on success;
3. reloads the page on a 3D route world (`[data-world-route]`), so the world is rebuilt in the new language under a fresh loading ceremony, otherwise calls `router.refresh()` (client state survives).

**Data locale.** `dataLocale` (Pokémon names) is the UI locale, or `'en'` when the viewer keeps Pokémon terms in English. English UI never shows German data names. The Pokémon layer reads it through `useDataLocale()` / `getDataLocale()` / `getRequestDataLocale()` and adds no cookie, provider or toggle of its own.

**API errors** (`api-errors.ts`, `use-api-error.ts`).
- Server: `UserFacingError` carries a typed `code` and `params` (`src/lib/api/user-facing-error.ts`); `safeErrorResponse(err, fallback, status?, fallbackCode?)` returns `{ success: false, error, code, params }`. The English `error` text is never changed (route tests assert it). Codes are flat keys, unique across all catalogs, snake_case except `errors/draft` (UPPER_SNAKE).
- Catalogs: `errors/common` (network, unknown, `validation_failed`, rate limits, auth guards, JSON body, `locale_*`) plus one per domain: `auth`, `players`, `teams`, `tournaments`, `matches`, `seasons`, `admin`, `ai`, `broadcast`, `stats`, `draft`, `draft-legacy`.
- Client: store the failure object, never its text, and render it during render:

```tsx
const errorText = useApiErrorText(errorsSeasons);       // errorsCommon is always included
const [error, setError] = useState<ApiErrorLike | null>(null);
if (!json.success) setError(json);
// …catch (e) { setError(toApiErrorLike(e)); }
{error && <p role="alert">{errorText(error)}</p>}
```

  Resolution: a known `code` is translated with its `params` (params named `pokemon`, `move`, `item`, … are English `@pkmn` names and go through a `PkmnParamLocalizer` when given); otherwise the English `error`; otherwise `unknown_error`.

**Viewerless text.** Text produced without a viewer uses the league's content language, `seasons.language` (`'de'` | `'en'`, default `'de'`; migration `20261012023655_seasons_language.sql`), set on the league form ("Content language (Discord, reports, overlays)").
- `resolveContentLocale({ seasonId?, tournamentId?, matchId? })` (server-only, React `cache()`, never inside `unstable_cache`) falls through season → tournament → match and defaults to `DEFAULT_CONTENT_LOCALE` (`'de'`). Standalone tournaments have no column and use the default.
- **Discord:** each webhook's `format_options.language` is `'league'` (default), `'de'` or `'en'`; `emitAsync` resolves the league language once per event and builds each embed in the webhook's language. Draft events take their copy from `draft/discord`.
- **Social images and posts:** the match social image is captured from a hidden copy wrapped in a nested `I18nProvider` in the content language when it differs from the viewer's.
- **Stored AI reports** follow the league (match → tournament → season); changing a league's language does not regenerate old reports. Live per-viewer AI (agent chat, team coaches) follows the viewer via `getRequestLocale(request)`. Prompts stay English with one output-language instruction line.
- **Broadcast overlays:** `resolveOverlayLocale(config, ref)` = `?lang=` → league language → `'de'`, never the cookie. Each `(broadcast)` page wraps its overlay in `<I18nProvider locale={l} dataLocale={l} timeZone={LEAGUE_TIME_ZONE}>`. The creator's overlay URL builder always writes `lang`.

**Caching.** The root layout's cookie read makes every route dynamic; the wiki pages lost their `revalidate` exports, and their heavy locale-neutral rows are memoized at module level (`src/lib/wiki/index-rows.server.ts`). Cached reads (`publicReads`, `unstable_cache`) hold DB data and English engine strings only and are translated after the read. Precomputing both locales into one cached value (`station-digest.ts`) is the only sanctioned exception. `src/i18n/__tests__/cache-boundary.test.ts` enforces this.

**Worlds.** Worlds follow the viewer (D11). Painters take `locale` from `useLocale()` in the component that builds the texture (it is in the `useMemo` deps), take their words from the `paint` / `world-themes` namespaces, fit every string with the measure-and-fit helpers in `src/lib/route-world/board-text.ts`, and upper-case with `upperForPaint`. Capture baselines exist per locale (`scripts/capture-route.mjs --locale de|en`).

### Dependencies

- **External libraries:** none added. React `cache()`, `next/headers` `cookies()`, `Intl` (`DateTimeFormat`, `NumberFormat`, `PluralRules`, `RelativeTimeFormat`, `ListFormat`) and the repo's `typescript` (for the string check).
- **Internal modules:** [PKMN](./pkmn.md) (`src/lib/pkmn/i18n`, consumes the data locale), [Draft Room](./draft-room.md) (draft namespaces and `errors/draft`), [Discord](./discord.md), [Broadcast](./broadcast.md), [Worlds](./worlds.md), [Validation](./validation.md) (`language` in the season and webhook schemas).

### API Routes

- **`POST /api/locale`** (public, no auth). Body `{ locale?: 'en' | 'de'; pkmnTerms?: 'follow' | 'en' }`, at least one key, unknown keys rejected.
  - A cross-origin `Origin` header → **403** `locale_cross_origin`.
  - An invalid body → **400** `locale_invalid`.
  - Success → **200** `{ success: true, data: { locale, pkmnTerms } }`: sets `plc_locale`; `pkmnTerms: 'en'` sets `plc_pkmn_lang=en`, `'follow'` deletes it.
  - A failure → `safeErrorResponse(…, 'locale_save_failed')`.

### Usage Examples

```tsx
// Client component
import { useT, useFormatter } from '@/i18n/client';
import { leagueAdminMessages } from '@/i18n/messages/league-admin';
const t = useT(leagueAdminMessages);
t('phases.deleteConfirm', { name: phase.name });
t('participants.count', { count: n });                        // plural object
t.rich('draft.setupHint', { link: (c) => <Link href={href}>{c}</Link> });

// Server component
import { getT } from '@/i18n/server';
const t = await getT(leagueAdminMessages);
// <LocalTime value={match.scheduled_at} preset="weekdayDateTime" />

// Viewerless text (Discord, reports)
import { createTranslator } from '@/i18n/core';
const lang = await resolveContentLocale({ seasonId });
const t = createTranslator(draftDiscordMessages, lang);
```

**Recipe for translating a file.**
1. Edit only the files and namespace directories you own; shared namespaces (`common`, `enums`, `glossary`, `content`, `errors/common`) are read-only. Put a truly cross-cutting key in your own namespace and flag it "for sweep".
2. The `en` value is today's English literal verbatim (exceptions: the unified enum wording; concatenated sentences become one message with placeholders). Write `de` per the style guide below, using the glossary terms exactly.
3. Plurals (`n !== 1 ? 's' : ''`) become plural objects; split sentences become `t.rich`; raw enum renders use `enumLabel`; engine names `translateEngineLabel`; dates `<LocalTime>` / `useFormatter()`; percentages `formatter.percentOf`; Pokémon names the pkmn layer with the data locale; module-level label constants become key arrays translated where they render.
4. Keep English: Showdown import/export text, stored DB values, URLs and sprite keys, AI prompts, `console.*` and log text, `aria-hidden` decorative glyphs.
5. Gate: `npx tsc --noEmit`, `npx vitest run <your tests> src/i18n`, `npx eslint <your files>`, and `node scripts/check-i18n-strings.mjs --paths "<your globs>"` with zero findings.

### Testing

- **Test files:** `src/i18n/__tests__/*` (core, rich, format, client, server, parity, typecheck fixtures, error codes, cache boundary, glossary/utility parity), `src/i18n/content/__tests__/engine-labels.test.ts`, `src/app/api/locale/__tests__/route.test.ts`, `scripts/__tests__/check-i18n-strings.test.mjs`.
- **Render tests:** the environment is `node` with `renderToStaticMarkup`. Existing English render tests stay green unwrapped (hooks fall back to English). Add at least one German assertion per migrated render-test file with `renderWithI18n(ui, { locale: 'de' })`; never rewrite an English expectation (the one sanctioned change is the unified enum wording, e.g. "In progress").
- **Parity:** `npm run build` type-checks `de` against `en`; `parity.test.ts` re-checks keys, placeholders and tags at runtime, which catches `as` casts.

**Hard-coded string check** (`scripts/check-i18n-strings.mjs`, allowlist `scripts/i18n-allowlist.json`). Inputs: `--paths <files|dirs|globs>`, `--all`, or (neither) the files changed against `${BASE:-origin/main}`. Report-only by default; `ENFORCE=1` exits 1 on findings. CI runs `--all` report-only during the translation waves; the i18n sweep flips CI and `scripts/verify-ci.mjs` to `ENFORCE=1` together.

| Rule | Flags | Where |
|---|---|---|
| `jsx-text` | JSX text with ≥ 2 letters | `src/{app,components,lib}`, not `src/app/api` |
| `jsx-attr` | a string literal in `aria-label`, `aria-description`, `title`, `placeholder`, `alt`, `label`, `subtitle`, `description`, `heading`, `message`, `emptyMessage`, `confirmLabel`, `cancelLabel`, `pendingMessage`, or any `*Label`/`*Text`/`*Title`/`*Message`/`*Placeholder` attribute | same |
| `call-arg` | a literal or prose template passed to `setError`, `setSuccess`, `setMessage`, `setStatusText`, `confirm`, `window.confirm`, `alert`, `toast*` | same |
| `jsx-expr` | a string literal or prose template rendered as a JSX child: `{'Save'}`, `{ok ? 'Yes' : 'No'}`, `{busy && 'Saving'}`, `{name ?? 'Unknown'}`, `{name \|\| 'Unknown'}`, `{'Total: ' + n}`, `` {tag`…`} ``, `{['a', 'b']}`, `{['a', 'b'].join(' ')}`, `{names.join(' and ')}`, also through `( )`, `x!`, `as`, `satisfies`. Both branches of `?:` and both sides of `??`, `\|\|` and `+` are walked; of `&&`, only the right side. A method call's receiver is walked only for the methods in `RECEIVER_RENDERING_METHODS` (`join`, `concat`, `toString`, `slice`, `filter`, `reverse`, `sort`, `toReversed`, `toSorted`, `flat`, `at`, `find`, `findLast`), so not the receiver of `.map(cb)`. Call arguments are not walked (`{t('key')}`, `{cn('…')}`, the callbacks and indices of `filter`/`find`/`at`), except those of `join` and `concat`: a join separator and concat payloads render | `src/{app,components,lib}`, not `src/app/api` |
| `object-text` | a string of ≥ 2 words, or with a capitalised word of ≥ 3 letters, under `label`/`title`/`description`/`text`/`message` in an object literal | `src/{app,components}`, not `src/app/api` |
| `locale` | `toLocale{Date,Time,}String()` without arguments; `Intl.DateTimeFormat(undefined…)` / `Intl.NumberFormat(undefined…)`; the literals `'en-US'`, `'en-GB'`, `'de-DE'`; `new Date()` / `Date.now()` during a component render (nearest named function is PascalCase) | all of `src` outside `src/i18n` |

Ignored: a line above holding `// i18n-ignore: <reason>` or `{/* i18n-ignore: <reason> */}` (the reason is required; for `jsx-expr`, a marker above the first line of a multi-line `{…}` child covers every string in it); allowlisted files; strings with no lowercase letter and length ≤ 4 (`HP`, `KO`, `VS`); punctuation and symbols; the allowlist tokens (`PokéTools`, `EvoLiga`, `Discord`, `Showdown`, `Pokémon`, `OBS`, `Smogon`, `Bo3`, `Bo5`, `Buchholz`) and `gen…` format ids; CSS/Tailwind-looking strings; URLs and paths; arguments of `console.*`, `logger.*`, `expect()`, `new …Error(` and `throw`; tests and `src/i18n/messages/**`.

**English-only by design decision** (allowlisted): Kale (`src/app/admin/kale/**`, soft-deprecated), the dev-only `/route-preview` fixtures and the `/draft-preview` fixture data (`draft-preview/{fixtures,fake-source}.ts`; its page is scanned), the route debug overlay, LLM and image-model prompts, parser sheet keys (`src/lib/import/**`), and `global-error.tsx` (providerless, inline bilingual copy).

### Studio namespaces (Ruleset Studio, league trash, shared studio shell)

- **Ruleset Studio.** `ruleset-studio` (the library, the New ruleset dialog, presets, usage and catalog-staleness texts: `list.usage.*`, `list.state.stale`, `list.staleHint`), and the sub-namespaces `ruleset-studio/{editor,sections,picker,summary,diagnostics,describe}` (the editor's chrome, the section panels, the entry picker, the live summary, the sentence for every compile diagnostic code, and the plain-sentence rules description). `ruleset-studio/sections` also holds the read-only page's `page.version*` change lines. The `ruleset` namespace (what other pages mount) holds `detail.*`, `select.*` (including `select.generationDoubles`), `pin.*` (the pin card and `pin.impact.*`, the count shown before a started league or phase moves to a newer version), `usage.*` and `presetSelect.*` (the rule-preset select shared by the Ruleset and Format Studios). The old builder keys (`banlist`, `builder`, `review`, `clauses`) and the `admin-tools` `rulesets.*` block were removed with the builder. Rule preset names (`Gen 9 OU`) and Showdown clause names are the catalog's own and stay English in every language; only the words around them are translated.
- **Shell words are per studio.** The shared `studio-shell` components take their words from a typed key set (`SHELL_KEYS` in `src/components/studio-shell/text.ts`) that each studio provides from its own namespace (`useShellText(rulesetStudioEditorMessages)`), so a neutral component never depends on a studio's messages. Add a shell key to both studios' catalogs or the types fail.
- **League recycle bin.** `league-admin` `trash.*` (the page, its columns, badges, notices and warning texts), `league-admin/season-page` `danger.*` (the delete hint), `shell` `guards.superadminOnly` and `admin.items.leagueTrash`, `ui` `deleteResource.confirm.season` (takes `{days}`). Other league forms: `league-admin` `form.rulesetLockedHint` (the read-only ruleset select), `league-clone` `picker.rulesetSame` (the source's ruleset line).
- **Error codes.** Ruleset codes (`ruleset_in_use`, `ruleset_pin_started`, `ruleset_pin_confirm_required`, `ruleset_pin_locked`, `ruleset_stale_revision`, ...) are in `errors/admin`; `errors/tournaments` has `ruleset_in_trashed_league`; `errors/seasons` has `LEAGUE_TRASH_*` and `INVALID_LEAGUE_TRASH_ID`, and `errors/admin` has `restore_rebuild_*` and the delete rebuild warnings. `src/i18n/__tests__/error-codes.test.ts` scans for undocumented codes (the shared `text-schema.ts` of the studio core is exempt).
- **German copy is not native-reviewed.** The German wording of the Ruleset Studio (Regelwerk, Regel-Preset, Smogon-Draft, the family names, clauses, the picker and the diagnostics) and of the league trash was written to the style guide below but has not been read by a native speaker.
- **English-only fixtures.** The dev previews `/ruleset-preview` and `/ruleset-preview/surfaces` render the real, translated components; only their fixture data (names, ids) is English.

### German Style Guide

**Voice.**
- Address the reader with *du*: lower case mid-sentence, "Du" only at the start of a sentence. The German games use *du*, the league is a casual Discord community, and mixing *du* and *Sie* is worse than either.
- Buttons use the infinitive ("Speichern", "Abbrechen", "Pick bestätigen", "Draften"); instructions use the *du*-imperative ("Wähle eine Linie aus.").
- People: generic masculine ("Spieler", "Teilnehmer"), no gender colon or star.
- Sentence case in both languages; never ALL-CAPS in a message (render caps with CSS or `upperForPaint`).

**Typography and formats.**

| Item | Rule |
|---|---|
| Numbers | `formatter.number`: `1.234,5` (de), `1,234.5` (en). Never a hand-made decimal point. Number params inside messages group from five digits (`min2`): `2026`, `12.345`. |
| Percent | `formatter.percentOf`: `12,5 %` (de, no-break space), `12.5%` (en). |
| Dates and times | the presets above; 24-hour clock in both. "Uhr" only inside sentences ("um {time} Uhr"), never in table cells. |
| Ranges | en dash without spaces: `25–20`, `S–N`. Spaced ` – ` as a sentence dash in de; avoid the em dash in de. |
| Quotes | de „…“ (U+201E … U+201C), nested ‚…‘; en "…" / '…'. Apostrophe ’ (U+2019). |
| Ellipsis | the single character … ; de puts a space before it ("Wird geladen …"), en does not ("Loading…"). |
| Compounds with English parts | hyphenated: "Draft-Raum", "Replay-Link", "Discord-Webhook", "Comeback-Token". |
| Abbreviations | `S/N/U` (W/L/D), `Pkt.` (Pts), `Sp.` (played), `EP` (Evolutionspunkte); `Bo3`, `KO`/`KOs` and `vs.` stay. |
| Points | the draft price `25 P` in both languages; long form "Punkte" / "points". |
| Length | German runs about 30 % longer: no fixed-width text containers; painters always use the fit helpers. |

### Emails

The Supabase Auth email templates are bilingual Go templates in `supabase/templates/{confirmation,recovery,email_change,magic_link,invite}.html`. Sign-up stores the viewer's language in `user_metadata.locale`; the template branches on it (`{{ if eq .Data.locale "en" }} … {{ else if eq .Data.locale "de" }} … {{ else }}` German, then English `{{ end }}`). Users created before this change get the bilingual branch. `supabase/config.toml` points the local stack at the same files.

The hosted templates live in the Supabase dashboard, so whoever runs the deployment updates them by hand:
1. Supabase Dashboard → Authentication → Email Templates.
2. For each template, paste the body from `supabase/templates/<name>.html`.
3. Set the subject to the bilingual string from `config.toml` (e.g. "Bestätige deine E-Mail-Adresse / Confirm your email"); subjects are not branched.
4. Save, then send a test sign-up in each language.
