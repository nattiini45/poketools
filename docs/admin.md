# Admin Module

> Site-wide administration surface: server-rendered management pages backed by a guarded admin API for data imports, exports, maintenance jobs, and moderation.

## Overview
The Admin module is a Next.js App Router surface (route group `/admin` and `/api/admin`) for running the platform. Two admin tiers reach it. Site admins (`player.isAdmin`) see everything. Resource admins (league or tournament admins in `resource_admins`) see the competition pages for their own leagues and tournaments.
- Every page is wrapped in `AdminGuard` (any admin, live read).
- Pages for one league, phase or tournament also call `gateResourceAdmin()` (`src/lib/auth/resource-gate.ts`) before any read and render `ResourceForbidden` for another league's admin.
- Every `siteAdminOnly` page in `adminNav.ts` uses `SiteAdminGuard`; a test walks the nav to enforce it.
- Scoped API routes (dashboard, matches, matches filter options, player search) call `requireAnyAdmin()` and narrow their reads with `getAdminScope()` (`src/lib/auth/admin-scope.ts`). All other `/api/admin` routes call `requireAdmin()`. Pages are thin server components that delegate to client content components (`*Console`, `*Manager`, `*Tools`) living alongside them; the API does the heavy lifting against Supabase and internal `src/lib` services.

## Core Functions/Classes

- **Auth guard** — `requireAdmin()` in `src/lib/auth/helpers.ts`: resolves the session player and throws `AuthError(403)` unless `isAdmin`. Pages additionally render through `components/shared/AdminGuard`. `requireAnyAdmin()` also lets a resource admin through, for the scoped routes.
- **Admin scope** — `getAdminScope()` in `src/lib/auth/admin-scope.ts`: from the live read, returns whether the caller is a site admin or the ids of the leagues and tournaments (with their phases) a resource admin may see. The dashboard, matches, filter-options and player-search routes and the archived lists narrow their reads with it.
- **Page gates** — `gateResourceAdmin()` in `src/lib/auth/resource-gate.ts` decides one league, phase or tournament page before it reads anything; `ResourceForbidden` is the "no access" notice. `SiteAdminGuard` wraps the pages that are site-admin only (the `siteAdminOnly` items of `adminNav.ts`).
- **Export rate limit** — `checkAndRecordAdminExport()` in `src/lib/admin/export-rate-limit.ts`: enforces `ADMIN_EXPORT_DAILY_LIMIT = 20` via the `check_and_record_admin_export` Supabase RPC, returning `{ allowed, remaining, reset_at }`.
- **Dashboard content** — `AdminDashboardContent.tsx`: live counts, attention-required matches, and recent audit activity fed by `/api/admin/dashboard`. A resource admin sees only the attention queue and counts of their own competitions; the site-wide counts and the activity feed are for site admins.
- **Matches list** — `/admin/matches` filters by status, league (with phase), tournament and a text search on the server (`status`, `season_id`, `tournament_id`, `q`), pages with `.range()` and an exact total, and keeps the filters in the URL. Each row shows its League and Phase. The League and Phase choices come from `/api/admin/matches/filter-options`.
- **Player pickers** — the roster, substitute, link, enrolment and league-admin pickers use the server-search `Combobox` (aborts a superseded request, shows a fetch error, waits for a minimum query length) over `/api/admin/player-search`; the Players page searches, pages and sorts on the server (`roster-helpers.ts`; `GET /api/players` takes `sort` = `name` | `discord_id` | `ps_username` | `status` and `dir` = `asc` | `desc`, default name ascending, and answers anything else with `400`).
- **Round deadlines** — `RoundManager` edits a round's deadline through `PATCH /api/tournaments/[id]/rounds/[rid]` (audited, expires the tournament's read tags) and flags an overdue round.
- **Aggregate maintenance** — `GET`/`POST /api/admin/aggregates`: query aggregate-job queue stats, or `drain` pending jobs / `rebuild` a scope (`tournament`, `league`, `all_time`) from `battle_stats`.
- **Reconcile** — `POST /api/admin/reconcile`: dry-run (`repair: false`) or repair season-derived data, scoped to one `season` or `all`.
- **Data export** — `POST /api/admin/export`: zod-validated CSV/JSON export of `players`, `tournaments`, `matches`, `seasons`, `games`, `battle_stats`, rate-limited and audit-logged.

- **Responsive shell** — `src/app/admin/layout.tsx` lays out the sidebar and the content column as a column below `lg` (`flex flex-col`), so the chip rows sit above the content, and as a top-aligned row from `lg` (`lg:flex-row lg:items-start lg:gap-8`). The content column keeps `min-w-0` (and `lg:flex-1` beside the rail), so its flex minimum is never its content's intrinsic width; wide content (tables) still needs its own `overflow-x-auto` wrapper on the page. ## League admin page (`/admin/leagues/[id]`)
One league's admin page is split into URL tabs (`?tab=`), like the public league hub (`src/lib/league-hub/tabs.ts`). Tab logic: `src/lib/league-admin/tabs.ts` (`availableLeagueAdminTabs`, the whitelist parser `parseLeagueAdminTab`, the old-id aliases `LEAGUE_ADMIN_TAB_ALIASES`, `leagueAdminHref`); page: `src/app/admin/leagues/[id]/page.tsx`; strip: `_components/LeagueAdminTabs.tsx`; one renderer per tab in `_components/panels/`.

| Tab (`?tab=`) | Shown for | Content | Reads beyond the league row |
|---|---|---|---|
| `overview` (default, bare URL) | all | Facts (format, ruleset, status, participant and phase counts, dates), link to the public league page, **Description** | none |
| `participants` | all | **Participants** (`LeagueRosterManager`), **League groups** (`LeagueGroupsEditor`), **Type Cores** (classic formats, collapsed) | none (client fetches) |
| `draft` | classic draft, EPB | Classic: **Draft Pool Pokémon**, **Draft Room** (`DraftPoolManager`). EPB: **Draft Room** (create summary or the active pool + control panel link), **Redraft** (control panel link), **Tokens** (`TokenAdminSummary`, on this tab only). A league with groups: one card per group (below) | the league's groups first; without groups the season's pool, EPB also participants, format rules, the pool list; with groups the pools with their groups, participants, format rules, the list's lines (while a group still needs its create form) and the Redraft refusal instants |
| `phases` ("Phases" / "Phasen"; the former `schedule` tab, and `?tab=schedule` still opens it) | all | **Phases** (`PhaseTimeline`; there is no league-scoped match list), **Evolution Points** (EPB) | rulesets |
| `rules` | classic draft, EPB | Classic: **Evolution Tiers**, **Draft Settings** (tier limits). EPB: **Point-Buy List**, **Format Rules**, **Data Import** (collapsed) | classic: participants (wildcard picker); EPB: none |
| `settings` | all | **3D World Theme**, **Content Language**; site admins also **Test League** and **League Admins** | none |
| `danger` | all | **Archive** / unarchive; **Delete league** (site admins, with the delete hint below; others see why it is missing) | none |

- Tab visibility comes from `getFormatCapabilities` (singles/doubles: overview, participants, phases, settings, danger; classic draft adds draft and rules; EPB has all seven). A missing, repeated, unknown or unavailable `?tab=` renders the overview; an old id from `LEAGUE_ADMIN_TAB_ALIASES` (`schedule`) opens its tab.
- Back-links into this page name their tab and go there: the draft control page ("Back to league admin: Draft", `?tab=draft`, also its legacy-pool "Manage" link and the draft room's "Go to league admin: Draft"), and a phase page ("← Back to <league>: Phases", `?tab=phases`). Build them with `leagueAdminHref(id, tab)`, never a bare `/admin/leagues/${id}`.
- **Delete hint** (Danger tab, site admins). It says what deleting the league takes with it, what refuses it and what it keeps. The lists come from `src/lib/league-admin/season-delete.ts`, derived from the schema's foreign keys: `season-delete.test.ts` replays every public migration's foreign keys and fails when one adds, drops or changes a cascade. `deleteSeason` is a single `DELETE FROM seasons`; the database does the rest:
  - **Deleted with it** (`ON DELETE CASCADE`, directly or through a cascaded table): participants; league groups and their members; format rules, evolution tiers, draft tier limits and the classic draft pool list; the evolution tracker with its events and progress log; token grants, Draft Kill Token purchases and Comeback Token spends; Redraft slots, submissions (through the tracker), history and trade requests.
  - **Refuses the delete** (no delete action on `season_id`): phases (`tournaments`), draft pools, teams and storylines. While the league still has any of them the delete fails; delete those first. The database refuses with SQLSTATE 23503, which the route answers as `409 SEASON_HAS_DEPENDENTS` (`errors/seasons`, en + de: delete the league's phases, draft pools, teams and storylines first).
  - **Kept, unlinked** (`ON DELETE SET NULL`): cast sessions.
  - Evidence of the live schema: the recursive `pg_constraint` query on the local stack with league groups applied (it also lists the groups' own keys: members cascade with the group (`season_group_members_group_fkey`, CASCADE); `draft_pools_season_group_fkey` and `tournament_groups_season_group_id_fkey` are ON DELETE RESTRICT, and `evolution_tracker_season_group_fkey` is NO ACTION. None of the three refuses anything a league delete would otherwise allow: a league with a draft pool or a phase is already refused through `draft_pools_season_id_fkey` / `tournaments_season_id_fkey` (both NO ACTION), and the tracker rows cascade away with the league in the same statement, before the NO ACTION check runs at its end), plus a rolled-back delete of a league with one phase that the database refuses with 23503 while a league without dependents deletes: transcripts `R4-UI-season-delete-fk-cascades.txt` and `R5-UI-season-delete-fk-proof.txt` (self-contained script `r4ui/fk-proof.sql`, which also lists the three group keys' delete actions).
- A route id that is not a uuid is a 404 before any read (`isValidUuid`), like the draft control page's `gateDraftAdmin`.
- The server renders, and reads for, the selected tab only (`searchParams` is read as a Promise). Every tab shares the league row and the live access read; the overview needs nothing else. A viewer who is not an admin gets only `AdminGuard` (denial or sign-in redirect) and no tab read runs.
- Site-admin-only parts (Test League, League Admins, phase delete, league delete) are decided from `getLiveAccess()` (the memoised live read the admin layout and `AdminGuard` share), never from the up-to-5-minute-old session copy. Writes stay guarded by their routes.
- Header on every tab: the test badge and `LeagueStatusControl` (status buttons, 44 px tall below `sm`, `aria-pressed`), in a wrapping row below the title rather than `PageContainer`'s non-wrapping `action` slot, so nothing widens the page at 375 px.
- Tab strip: a `<nav>` landmark (`tabs.label`) of `Link`s with `aria-current="page"` on the active tab, which also `aria-controls` the panel region (`#league-admin-panel`, labelled by the active tab). It scrolls sideways inside itself on a phone (`HubTabStripScroll` keeps the active tab in view), labels have no fixed width (German runs longer), tabs are 44 px tall below `sm`, theme tokens only, and the pending dot pulses only under `prefers-reduced-motion: no-preference`.
- Settings controls sit in plain (non-collapsible) sections and follow their server prop after a save (`useServerSyncedState` + `router.refresh()`), so a remount never shows a stale value. `EditableDescription` keeps unsaved text in the tab's sessionStorage (`src/components/shared/description-draft.ts`): a tab switch, collapse or reload no longer loses it, and the next mount offers it back (**Resume editing** / **Discard draft**); **Edit** opens an offered draft too, so its first keystroke never overwrites it; Save and Cancel drop it. A browser that refuses to store the draft (private mode, blocked or full storage) gets a short notice in the editor and a `console.warn`. These buttons are 44 px tall below `sm`.
- **Other unsaved forms and tab switches.** A tab switch is a navigation: the open panel's forms unmount. Only the description keeps a draft. Every other form opts into a guard: while it holds unsaved input it marks its root `data-unsaved="true"` (`unsavedMarker(dirty)` from `src/lib/league-admin/unsaved.ts`) and drops the marker once the input is saved or discarded. While any marked element is inside the panel region (`#league-admin-panel`), `UnsavedTabGuard` (mounted by the tab strip) asks with the browser's confirm dialog before a tab switch (`tabs.unsavedConfirm`, en + de; declining keeps the tab and its input), and the browser asks before a reload or close. A click on the open tab, or one that opens a new tab or window, is never interrupted. Opt-in, because only the form knows when its input is saved (a DOM-level "something was typed" guard would also fire after a successful save). Forms that mark themselves, each deciding through one pure predicate in `src/lib/league-admin/form-dirty.ts`: the phase form (`PhaseForm`, Phases tab: a field differs from what it loaded, or from what it last saved; a best-of override of 0 counts as none), the tier limits (`DraftTierLimitsEditor`, Rules tab, classic draft: a limit differs from the loaded or last saved ones) and the classic draft pool editor (`DraftPoolEditor`, Draft tab: the open add form has a search, a chosen Pokémon or a cost entered, or a template name is typed; the inline row edits save on change and never count). No other form on the page marks itself yet (the description keeps its own draft instead).
- **Rules tab for classic draft (decision, round 3).** Proposal A put classic Evolution Tiers and Draft Settings under the Draft tab; they sit on the Rules tab (the classic-draft brief), and the Draft tab holds the pool and the Draft Room. Confirmed as is.
- Copy: namespace `league-admin/season-page` (`tabs.*`, `overview.*`, `danger.*` with `danger.deletes.*` / `danger.blockers.*`), en + de. The EPB Draft Room hints link the Rules or Participants tab (`<link>` rich text). League groups: namespace `league-admin/groups` (`editor.*`, `draft.*`), en + de.

### League groups
A league may split its trainers into groups (design: one round robin, one table and one draft per group; schema and draft engine: [Draft Room, League groups](./draft-room.md#overview)). Leagues without groups behave exactly as before.
- **Editor** (Participants tab, `src/components/league/groups/LeagueGroupsEditor.tsx`, a client component; its markup is `LeagueGroupsEditorView`). It loads `GET /api/seasons/[id]/groups` (league admins only: the groups with their members and a `locked` flag per group, the roster in seed order as `{ id, name, seed }`, `replaceLocked`, and `scheduleLocked`: a phase of the league has a round) and writes through (`editor-requests.ts`: the requests and how each answer maps; after a rename or a refusal the editor re-reads its data, so a lock that arrived meanwhile shows at once):
  - `PUT /api/seasons/[id]/groups` — `{ mode: 'serpentine', group_count }` splits by seed (snake order: the seeds run through the groups in order, then back in reverse, so two groups get 1 → A, 2 → B, 3 → B, 4 → A; seeds from the league's first phase, unseeded trainers after them by name; existing groups keep their names by position, new ones take the next `Group X` no kept group uses, so a group renamed to "Group C" never collides; every group needs two trainers, else `422 SEASON_GROUPS_TOO_MANY`), `{ mode: 'manual', groups: [{ name, player_ids }] }` sets them as given (every participant exactly once: `422 SEASON_GROUPS_INCOMPLETE` / `SEASON_GROUP_PLAYER_NOT_FOUND`; two trainers per group: `422 SEASON_GROUP_TOO_SMALL`), `{ mode: 'clear' }` removes every group (behind a confirm dialog). One transaction (`season_groups_replace`, which checks the same rules again: every participant in exactly one group, two per group); refused once a phase of the league has a round (`409 SEASON_GROUPS_SCHEDULED`), while any group has a live draft pool or drafted lines (`409 SEASON_GROUP_LOCKED`), or when a removed group is still used (`409 SEASON_GROUP_IN_USE`). Audited as `season.groups.replace` (before/after groups and members).
  - `PATCH /api/seasons/[id]/groups/[groupId]` — rename (`{ name }`, 1–60 characters; allowed at any time, also while the group drafts and after the first round). `404 SEASON_GROUP_NOT_FOUND` for a group of another league, `409 SEASON_GROUP_NAME_TAKEN` for a name another group of the league has, ignoring case and blanks (`uq_season_groups_name_ci`), `422 INVALID_CONFIG {field: name}` when the table's length check refuses it. Audited as `season.group.rename`.
  - `PATCH /api/seasons/[id]/groups/members` — `{ player_id, group_id }` moves a trainer, or places a participant who joined after the split (they appear under "Not in a group"). The database guard refuses it once a phase of the league has a round (`409 SEASON_GROUPS_SCHEDULED`), while the old or the new group has a live (not cancelled) pool or the trainer holds lines of the old group (`409 SEASON_GROUP_LOCKED`), and when it would leave the old group with one trainer (`422 SEASON_GROUP_TOO_SMALL`). A roster or group change racing the route's own checks keeps distinct codes (`422 SEASON_GROUP_PLAYER_NOT_FOUND`, `404 SEASON_GROUP_NOT_FOUND`). Audited as `season.group.member.place` (from → to).
  - Every route guards its path ids first (`404 INVALID_SEASON_ID` / `INVALID_GROUP_ID`; pinned in the shared `src/app/api/__tests__/path-id-guards.test.ts`, with the phase groups routes and `GET /api/drafts?season_id=`), validates its body with a strict zod schema (`_lib/schemas.ts`), answers database refusals with their `errors/draft` codes and expires the league's and the draft pages' cached reads. Group names are stored as typed (the defaults as English engine names) and shown through `translateEngineLabel('group', …)` (`Group A` → `Gruppe A`).
  - The editor offers split by seed, clear, rename and move; a custom split is the seeded split followed by moves (or the moves alone, for trainers placed later). `mode: 'manual'` is for scripted bulk replacement through the API only (every participant must be named exactly once, so an editor form for it would be the same as split + move).
  - **Roster (Participants card).** Adding and removing trainers honours the same rules, because leaving the league leaves the group: removing a trainer who holds a group (`DELETE /api/seasons/[id]/participants`, RPC `season_participant_remove`, `20261018202100`) is refused once the league has a round (`409 SEASON_GROUPS_SCHEDULED`), while that group has a live pool or the trainer holds lines drafted in it (`409 SEASON_GROUP_LOCKED`), and when the group would keep one trainer (`422 SEASON_GROUP_TOO_SMALL`); adding a trainer to a grouped league that already has a round is refused (`409 SEASON_GROUPS_SCHEDULED`: they could join no group and would have no fixtures). The roster manager shows the refusal in the viewer's language (`errors/draft`). Use a substitution instead: it keeps the slot and its group. A trainer in no group, and every trainer of a league without groups, is added and removed as before.
  - **Why the groups freeze at the first round** (lead ruling round 4): the phases mirror the league groups when their first round is generated, and the schedule, the group tables, per-group advancement and the per-group Redraft order all build on that membership. A move afterwards would hand a trainer another group's draft, tokens and table while the schedule kept the old group, so every membership change is refused from then on; substitutions still work (the incoming trainer takes the slot). Rules in full: [Season, League groups](./season.md#league-groups-schedule-and-standings).
  - UI: a group with a draft shows "Has a draft" and its member selects are disabled; it is no move target for others; once any group drafts, re-split and remove are hidden and an amber note says why. Once the league has rounds, an amber note says the groups are final, every group shows "Fixed" (the badge's reason is also read to screen readers), every member and placement select is disabled and only Rename stays. A group at two trainers keeps them: its selects are disabled and point (`aria-describedby`) at the line saying why. Selects and buttons are 44 px tall below `sm`; the rename form returns focus to its Rename button on Save, Cancel or Escape; saves are announced in a polite live region; refusals render from their code (`errors/seasons`, `errors/draft`).

### Draft tab with league groups
`groupedDraftPanel` (`_components/panels/DraftPanelGroups.tsx`) replaces the single-pool Draft Room in a league with groups:
- **EPB:** an intro, then one card per group (name, member count) with its pools: Initial draft and Redraft, each with its phase, a link to the control panel (`?pool=<id>`) and to the draft room (`?pool=<id>`), and, for a Redraft still collecting drops whose automatic publish was refused, the amber "Automatic publish refused at <time>" line from `draft_pools.publish_refused_at` (admin data, `loadPublishRefusals`; never in a public snapshot). A group without an Initial draft gets the create summary (`EpbDraftRoomCreate` with `seasonGroupId`; seats "One per group member") behind the gates: no list bound, no members, fewer than the seat minimum, more than the maximum, and the completability check (`DraftGroupGate.ts`, the TS twin of `draft_start`'s check with every member at the format-rules budget and roster size over the whole list): a group that could never fill every roster gets an amber warning telling the admin to split the participants into smaller groups, and no create form. A participant in no group is named above the cards (they get no seat). The Tokens summary keeps the Comeback switch until every group's Redraft has completed.
- **Other formats:** groups draft only in Evolution Point Buy leagues (the legacy engine has no seats); the Draft Room explains it and links the Participants tab, and `POST /api/drafts` refuses a legacy pool in a league with groups (`409 draft_groups_need_point_buy`).
- The draft_start refusal `LEAGUE_NOT_COMPLETABLE` (en + de) now also tells the admin to split the participants into smaller groups on the Participants tab (owner ruling, round 2).

## Draft control (`/admin/leagues/[id]/draft`) and the room's admin sheet
- **League groups.** The control page lists every queue pool of the league as a tab (`getDraftPoolsBySeasonWithGroups`: by group, then creation), labelled by group ("Group A · Initial draft", "Group A · Redraft 1"; Redrafts are numbered per group); the audit trail's pool tabs read the same. "Create Redraft" follows the selected tab's group: it reads "Create Redraft for Group A" and posts that group's `season_group_id` to `POST /api/drafts` (whose Redraft seats are the group's members, ordered by the group's own first-half table); the room's admin sheet does the same for the room's pool. A league without groups keeps the plain labels and the season-wide "Create Redraft" with the unchanged body. The Draft tab's per-group cards link each pool with `?pool=<id>`, so a group's control panel link lands on that group's tab.
- The control page keeps every per-pool section (live controls, Redraft, settings, picks, penalties) stacked in cards, one pool tab at a time with its own snapshot poll, plus "Create Redraft". The token balances and the Comeback switch are not here any more: `TokenAdminSummary` lives on the league admin page's Draft tab only (owner feedback: no duplicate), and a **Tokens** card links there ("League admin: Draft"). The pool tabs are a keyboard tablist (Left/Right/Home/End, roving tabindex, `aria-controls` on the selected tab) and 44 px tall below `sm`. `?pool=<id>` opens that pool's tab (validated against the season's queue pools; otherwise the running pool, else the newest), so the room sheet's "Full draft control" link lands on the room's pool. Gate: `gateDraftAdmin` (live, site admin or resource admin of the season).
- During a draft, pool admins work in the draft room instead: its clock row has an **Admin** button that opens the admin sheet (`RoomAdminSheet`) with the same sections as tabs (Live, Picks, Settings, Redraft, Penalties), fed by the room's own snapshot poll, plus links to the audit trail and the control page. "Pick for the active player" there switches on the room's admin override instead of linking to the room. Details: [Draft Room, Admin sheet in the room](./draft-room.md#admin-sheet-in-the-room).
- **Refused automatic publish.** When the deadline tick refused to publish a Redraft (`REDRAFT_NOT_COMPLETABLE` / `POOL_CHECK_LIMIT`; it retries after a pool change or an hour later), the Redraft section shows an amber notice "Automatic publish refused at <time>" with what to do (move the deadline, or force publish with a reason), on the control page and on the room sheet's Redraft tab. The time is `draft_pools.publish_refused_at`, read through one query module (`src/lib/supabase/queries/draft-publish-refusals.ts`) by two admin-only paths: the control page's server render (`loadPublishRefusals`, only for Redrafts still in their submission phase, so most pages make no extra read) for its first render, and `GET /api/drafts/[id]/redraft/submissions` (`{ submissions, publish_refused_at }`), which the Redraft section reads itself and which wins once it answers. The section re-reads it on a state version or phase change, and once a minute while the Redraft is locked, since the tick's refusal bumps no state version. The draft snapshot never carries it, for any viewer (`draft__build_snapshot` does not emit it and the TS mapper `src/lib/draft/snapshot.ts` would not map it): the query module is the single delivery path. Previews: `/draft-preview?scenario=admin-publish-refused` (control page), `admin-room-refused` (room sheet).
- Both surfaces render the shared sections from `src/components/draft-admin/pool-admin.tsx`; destructive actions are red on the control page and amber in the room; main actions use the theme accent on the control page and a neutral draft-ink outline in the room.

## Data Flows
- **Read**: admin pages (server components) query Supabase via `src/lib/supabase/queries/*` and render through `AdminGuard`; the dashboard pulls live aggregates from `/api/admin/dashboard`.
- **Write**: mutations go through `/api/admin/*` routes, which call `requireAdmin()`, validate input (zod schemas from `src/lib/validation`), execute against Supabase or internal services, and emit audit events via `logAuditEvent()`.
- **Maintenance**: long-running jobs (`aggregates`, `reconcile`) set `maxDuration = 300`; exports are capped by the daily rate-limit RPC and stream CSV/JSON back to the browser.

## API Routes
All routes call `requireAdmin()` unless noted below (the scoped dashboard, matches, filter-options and player-search routes call `requireAnyAdmin()`), and return `ApiResult` envelopes; errors go through `safeErrorResponse`.

- **Dashboard & audit**: `/api/admin/dashboard` (counts + attention + activity; scoped to the caller's leagues and tournaments for resource admins, who get no site-wide counts and no activity feed), `/api/admin/audit-log`.
- **Player search**: `/api/admin/player-search` (any admin; a resource admin must name a `season_id` or `tournament_id` they administer, which is a guard and not a filter: the search covers the whole directory, but a resource admin sees only what the public player directory shows, so banned, suspended and test accounts stay hidden, while a site admin sees every account; returns public refs only; `registered=1` keeps only accounts with a login). Used by the roster, substitute, link, enrolment and league-admin pickers (`src/lib/players/player-search.ts`).
- **Data export/import**: `/api/admin/export`, `/api/admin/players/import`, `/api/admin/import-sets`, `/api/admin/import-sample-sets`, `/api/admin/import-stats`, `/api/admin/import-usage-stats`, `/api/admin/import/point-buy`, `/api/admin/import/team-roles`.
- **Match/game operations**: `/api/admin/matches` (any admin, scoped; server-side `status`, `season_id`, `tournament_id`, `q`, `page` (1 to 1000), `page_size` with an exact total), `/api/admin/matches/filter-options` (scoped leagues with phases, and standalone tournaments), `/api/admin/matches/[id]/reset`, `/api/admin/matches/[id]/replay-import`, `/api/admin/matches/[id]/replay-preview`, `/api/admin/games/[id]`.
  - Replay import (`/import-replay`, `replay-preview` + `replay-import`): the organizer assigns the two replay sides to the participants; the winner and stats are the replay's own and are not editable in the form (correct them afterwards in the game editor). The import sends the preview's `replay_hash` back and is refused with 409 `replay_changed_since_preview` when the replay changed, or 409 `replay_already_recorded` when the battle is already recorded for any game. See `docs/match.md` ("Replay Binding").
  - The per-match admin pages (`/admin/matches/[id]`, `/import-replay`, `/games/[gid]/edit`) need more than `AdminGuard`'s any-admin check: the viewer must be a site admin or a resource admin of that match's tournament or league. `canAdministerMatch(match.tournament_id)` in `src/app/admin/matches/[id]/match-access.tsx` decides it from the live `getLiveAccess()` read; any other admin sees `MatchAccessDenied`. It is the same rule as `/api/admin/matches/[id]/reset` and `/api/admin/games/[id]`.
- **Player discipline**: `/api/admin/players/[id]/suspend`, `/api/admin/players/[id]/unsuspend`. Timed suspensions are lifted by the `/api/cron/expire-suspensions` cron (every 15 minutes, one audit event per player).
- **Achievements & gamification**: `/api/admin/achievements`, `/api/admin/achievements/[id]`, `/api/admin/backfill-gamification`.
- **Maintenance jobs**: `/api/admin/aggregates`, `/api/admin/reconcile`, `/api/admin/rounds/[id]/reset`.
- **Wiki moderation**: `/api/admin/wiki/notes`, `/api/admin/wiki/reports`, `/api/admin/wiki/reports/[id]`.
- **Testing**: `/api/admin/test-players`.
  - Test leagues: a site admin marks a league as one on `/admin/leagues/[id]?tab=settings` (**Test League** section, checkbox *Test league — listed with a test badge, excluded from ratings and all-time stats*, `LeagueTestFlagControl`). It PATCHes `{ is_test_season }` to `/api/seasons/[id]`, which refuses league admins (**403**), audits `season.set_test_flag` and expires the league's reads and the season list. Every request that sends the flag (changed or not) rebuilds the ratings of the league's players (test leagues stay out of ratings), so sending the same value again finishes a cut-off rebuild. That re-send is an API path: the checkbox only sends a changed value, so here it means switching the flag off and on again (two rebuilds) or running the repair. When that rebuild fails, or reaches its pass cap before the ratings settle (`test_flag_rating_rebuild_unsettled`), the flag stays saved and the control shows the response's `rebuild_warning` under the checkbox (*Rating rebuild: …*): repair with Record Reconciliation for that league (it covers every player of the league's completed matches, including players who left the roster), repeating the repair until its dry run lists no rating mismatch (one repair run is a single rebuild pass). A save without an answer refreshes the checkbox to the stored flag and says the save is unconfirmed. Public league lists, the home teaser and My Leagues show test leagues after the real ones with a **Test league** badge (the insights scope picker and the home spotlight leave them out); the admin lists badge them **Test**. Details: [Season](./season.md#test-leagues).
