# Admin Module

> Site-wide administration surface: server-rendered management pages backed by a guarded admin API for data imports, exports, maintenance jobs, and moderation.

## Overview
The Admin module is a Next.js App Router surface (route group `/admin` and `/api/admin`) for running the platform. Two admin tiers reach it. Site admins (`player.isAdmin`) see everything. Resource admins (league or tournament admins in `resource_admins`) see the competition pages for their own leagues and tournaments.
- Every page is wrapped in `AdminGuard` (any admin, live read).
- Pages for one league, phase or tournament also call `gateResourceAdmin()` (`src/lib/auth/resource-gate.ts`) before any read and render `ResourceForbidden` for another league's admin.
- Every `siteAdminOnly` page in `adminNav.ts` uses `SiteAdminGuard`, and every `superadminOnly` page (the league trash) uses `SuperadminGuard` (the live `getLiveAccess().isSuperadmin`); a test walks the nav to enforce both (the soft-deprecated Kale console is the one exception).
- Scoped API routes (dashboard, matches, matches filter options, player search) call `requireAnyAdmin()` and narrow their reads with `getAdminScope()` (`src/lib/auth/admin-scope.ts`). All other `/api/admin` routes call `requireAdmin()`. Pages are thin server components that delegate to client content components (`*Console`, `*Manager`, `*Tools`) living alongside them; the API does the heavy lifting against Supabase and internal `src/lib` services.

## Core Functions/Classes

- **Auth guard** — `requireAdmin()` in `src/lib/auth/helpers.ts`: resolves the session player and throws `AuthError(403)` unless `isAdmin`. Pages additionally render through `components/shared/AdminGuard`. `requireAnyAdmin()` also lets a resource admin through, for the scoped routes.
- **Admin scope** — `getAdminScope()` in `src/lib/auth/admin-scope.ts`: from the live read, returns whether the caller is a site admin or the ids of the leagues and tournaments (with their phases) a resource admin may see. The dashboard, matches, filter-options and player-search routes and the archived lists narrow their reads with it.
- **Page gates** — `gateResourceAdmin()` in `src/lib/auth/resource-gate.ts` decides one league, phase or tournament page before it reads anything; `ResourceForbidden` is the "no access" notice. `SiteAdminGuard` wraps the pages that are site-admin only (the `siteAdminOnly` items of `adminNav.ts`).
- **Export rate limit** — `checkAndRecordAdminExport()` in `src/lib/admin/export-rate-limit.ts`: enforces `ADMIN_EXPORT_DAILY_LIMIT = 20` via the `check_and_record_admin_export` Supabase RPC, returning `{ allowed, remaining, reset_at }`.
- **Dashboard content** — `AdminDashboardContent.tsx`: live counts, the attention list and recent audit activity fed by `/api/admin/dashboard` (contract in `src/lib/admin/dashboard.ts`). The attention list shows the matches that have waited longest first, each with League and Phase (or the tournament for a standalone one), the waiting time and, for a disputed match, its note. The header reads "N of M" when more matches need attention than are listed, and the footer has one See all link per non-zero status into `/admin/matches?status=…`. The counter cards link to their lists (players, tournaments, active matches, leagues; games has no list). Counts and the list leave out test leagues and archived competitions; the players total also leaves out test accounts. A resource admin sees only the attention queue and counts of their own competitions; the site-wide counts and the activity feed are for site admins.
- **Matches list** — `/admin/matches` filters on the server and keeps every filter in the URL (`parseMatchListUrl` / `buildMatchListSearch` in `src/lib/admin/match-list.ts`). Always visible: the text search (player, Showdown username or a pasted match id), League, Phase, Round (loaded per phase from `/api/admin/matches/filter-options/rounds`), the status tabs, four quick filters (awaiting confirmation, auto-confirms within 24 h, stale in progress, overdue; one at a time, narrowing the status), the sort and the chips of every active filter with a Clear all button. A collapsed "More filters" disclosure holds the date filter (field: scheduled, played, created or updated; from/to, or today, next 7 days, last 7 days, no date set), the format filters (league format, bracket type, best-of, ruleset), the player filter (with an optional head-to-head opponent, searched through `/api/admin/player-search`), the content filters (replay, hand-edited stats, admin notes, no games recorded) and the visibility toggles. Calendar days are computed in the viewer's time zone (`src/lib/admin/match-list-dates.ts`) and sent to the API as ISO instants (`date_from` inclusive, `date_to` exclusive). Test leagues and archived leagues and tournaments are hidden unless `include_test` / `include_archived` are set; naming a league, a phase or a match id shows its matches anyway. Sorts: newest first (default), needs attention first (disputed, awaiting confirmation, in progress, scheduled, completed; oldest waiting first inside a status, which costs up to five count queries per request), scheduled time and round deadline (rows without one last) and last updated. The stale threshold is `ADMIN_MATCH_STALE_IN_PROGRESS_DAYS` in `src/lib/admin/match-list.ts`; the overdue filter needs a round deadline, so a round without one is never overdue. - **Player pickers** — the roster, substitute, link, enrolment and league-admin pickers use the server-search `Combobox` (aborts a superseded request, shows a fetch error, waits for a minimum query length) over `/api/admin/player-search`; the Players page searches, pages and sorts on the server (`roster-helpers.ts`; `GET /api/players` takes `sort` = `name` | `discord_id` | `ps_username` | `status` and `dir` = `asc` | `desc`, default name ascending, and answers anything else with `400`).
- **Round deadlines** — `RoundManager` edits a round's deadline through `PATCH /api/tournaments/[id]/rounds/[rid]` (audited, expires the tournament's read tags) and flags an overdue round.
- **Start-up guardrails** — above Generate, `RoundManager` shows a setup checklist (participants, ruleset, best-of, league groups, seeding, previous round, round robin rounds remaining; `src/lib/tournament/startup-checklist.ts`) and disables Generate while an item is blocked, saying why. A generated round stays pending until it is started, so a banner offers a one-click Start for the next pending round, and Generate has a default-off "Start the new round right away" option (the generate routes accept an optional `{ "start_round": true }` body). A round robin with every round generated shows "All N rounds generated" instead of Generate. Details: [Tournament](./tournament.md#start-up-checklist).
- **Rulesets (Ruleset Studio)** — `/admin/rulesets` is open to every admin tier (the Rulesets item of `adminNav.ts` is not `siteAdminOnly`). The old five-step builder (`RulesetBuilder`, `ClauseToggleGrid`, `BanlistEditor`, `FormatChangeDialog` and the "safe format switch") is gone; a ruleset is now a definition with published versions, edited in the studio editor. Pages, the editor, the pin card and the permission matrix: [Ruleset Studio](./ruleset-studio.md). What the rest of the admin surface mounts from it:
  - **Ruleset selects** (`RulesetSelect`) on the league, phase and tournament forms are version-aware: they show the head version of each ruleset the admin may use and keep every version the form already holds, so an older pin is never shown as something else.
  - **Pin card** (`RulesetPinCard`) on the league Settings tab, the phase page and the standalone tournament page, and the **usage panel** on a ruleset's read-only page: the pinned version, a newer one, what changed, and "update", which for a started league or phase first asks how many submitted teams would stop being valid. A started league's Settings select is read-only; the pin card is the way to a newer version.
  - **Team constraints** are edited in the studio editor (`TeamConstraintsEditor`, Team constraints section); an enabled block with no rule is stored as `null`, and an untouched stored empty object stays as it is.
- **Start from an existing league** — `/admin/leagues/new` has a **Start from** picker (the 100 newest leagues the caller administers, archived and test leagues included; a site admin sees all leagues, a league admin only their own). A chosen source prefills league type, battle ruleset, theme, content language and description; the name and the dates always come from the form and stay as typed when the source is picked or changed. `POST /api/seasons` accepts `clone_from: { season_id, copy_roster, copy_admins }` and, after creating the league the normal way, copies the source's phases (name, description, bracket type, ruleset, best-of and overrides, doubles, team visibility, grand-final reset and advancement rule; renumbered from 1 and created as upcoming phases, enrolled through `syncStandingsEnrollment`). **Copy the roster** adds the source's players (ids only), **Copy the league admins** (site admins only) grants the source's league admins. Never copied: rounds, matches, games, phase participants and seeds, results, league groups, point-buy lists, tokens, draft data and format rules (a point-buy destination gets its own format rules and list binding as usual). If any step fails, the new league is rolled back (phases, admin grants, then the league) and the request answers `SEASON_CLONE_FAILED`; if the cleanup also fails it answers `SEASON_CLONE_CLEANUP_FAILED` and names what remains. Audited as `season.clone` and `season.clone_failed`. Details: [Season](./season.md#create-a-league-from-another-league-post-apiseasons-clone_from).
- **Format drift report** — `/admin/data` has a **Format drift report** section for site admins. **Run report** fetches `GET /api/admin/format-drift` on demand (nothing is read when the page opens) and lists, read-only, where stored settings differ from the format pack or from what the engine reads: leagues whose stored tiebreaker order differs from the format pack default (information only: the standings use the stored order; a stored order the standings cannot use is marked, because the table then falls back to the pack default), and consecutive phase pairs whose advancement rule sits on the source or the target phase or differs between them (enrollment sync reads the rule from the phase being enrolled, while the phase timeline shows it on the phase before). It writes nothing and fixes nothing. Each list links to the league's Rules or Phases tab and to the phase pages; each read is bounded at 10,000 rows and the report says when it is partial. The route answers site admins only; league admins get `403` because it spans every league. Logic: `src/lib/admin/format-drift.ts`, reads: `src/lib/supabase/queries/format-drift.ts`.

## Layout and navigation
- **Shell** — the admin has its own shell instead of the public NavBar (redesign A1). `src/app/admin/layout.tsx` reads `getLiveAccess()` once: a live admin gets `AdminShell` (`src/components/admin/AdminShell.tsx`: `AdminSidebar`, `AdminTopBar`, `AdminCommandMenu`) around `<main id="main-content">`; anyone else gets `<main>` with `AdminGuard` alone (redirect to sign-in, or the admin-only notice), so the admin IA never renders for a non-admin. The per-page guards stay as defense in depth.
- **Sidebar** — `AdminSidebar` renders the role-filtered groups of `adminNav.ts` (`visibleAdminNav`) on the @fluid sidebar: **Run** (Overview, Competitions, Matches, Players), **Library** (Formats, Rulesets), **Community** (Achievements, Wiki moderation, Social) and **System** (Data tools, Meta data, Audit log, Test players, Assistant, Kale console, then the pack extension's pages), which is folded until the page is inside it. Competitions (`/admin/leagues`) is one section over five list URLs; its views (Leagues, Tournaments, Archived leagues, Archived tournaments, and League trash for the superadmin) show under it while the page is in the section. Formats is not `siteAdminOnly`: resource admins see it. Exactly one item carries `aria-current="page"`, the one with the longest matching href (`activeAdminNavHref`); the section above a view carries `aria-current="true"`. The rail is dark umber in both themes (`data-theme="dark"` on `.admin-rail`, `globals.css` "Admin shell"), the current section sits on a gold skewed plate, and items carry the approved item icons (`nav-icons.tsx`). Header: wordmark, **New competition** (`/admin/leagues/new`) and the command-menu field. Footer: Back to site (`/dashboard`) and the account menu (profile, settings, theme, language, sign out; name and avatar from the session copy, display only). The sidebar collapses with `[`, resizes from its edge, remembers its state in the `sidebar_state` cookie (read by the layout) and is a drawer below 768 px that closes on navigation; rows are 44 px in the drawer.
- **Top bar** — `AdminTopBar`: sidebar toggle, breadcrumb, command-menu button, the assistant launcher (where the assistant is on for the viewer) and the notification bell. The breadcrumb (`admin-breadcrumb.ts`, `AdminBreadcrumb`) starts at the sidebar item and names the steps below it; a page that knows its subject's name mounts `<AdminCrumbName href name>` (`admin-crumb-names.tsx`), otherwise the step shows a generic label ("League"). A new admin route below a sidebar item adds its trail to `TRAILS`.
- **Command menu** — `AdminCommandMenu` (⌘K / Ctrl+K, @fluid `command-menu`) lists the pages `visibleAdminNav` gives this viewer and the shell's actions (New competition, Open assistant, switch theme, switch language, Back to site). It does not search competitions: that needs an admin-scoped index route, which is not approved.
- **Assistant launcher** — the floating pill is gone. The drawer opens from the top bar's button, the command menu (both through `openAdminAssistant()`) and the `.` key; the Assistant sidebar item opens the full page.
- **Competition list** — the five list pages (`/admin/leagues`, `/admin/tournaments`, their `archived` pages and `/admin/leagues/trash`) render one `CompetitionList` (`src/components/admin/competitions/`, redesign A4): a Leagues | Tournaments switch, an Active | Archived (| Trash for the superadmin, leagues only) filter, a search box that narrows the rows already loaded (name, format, ruleset; it reads no more data) and one next-step link per row (Set up, Manage, Review or Open, from the status). The pages keep their guards and reads and map rows with `toLeagueRow` / `toTournamentRow` (`src/lib/admin/competition-list.ts`); the trash view wraps `LeagueTrashPanel` in the same chrome. Copy: `admin-competitions` namespace. Below `xl` a row is a card with labelled fields. Query budget: `src/app/admin/__tests__/competition-list-query-budget.test.ts`.
- **Responsive shell** — the content column beside the sidebar keeps `min-w-0`, so its flex minimum is never its content's intrinsic width; wide content (tables) still needs its own `overflow-x-auto` wrapper on the page. `<main>` is capped at 1440 px. Tests: `src/components/admin/__tests__/admin-layout-responsive.test.tsx`, `admin-nav-active.test.tsx`, `admin-breadcrumb.test.ts`, `admin-command-menu.test.tsx`.

- Tab visibility comes from `getFormatCapabilities` (singles/doubles: overview, participants, phases, format, settings, danger; classic draft adds draft and rules; EPB has all eight; a `custom` league has the singles-like set plus the **Live** tab, seven in all, see the `live` row). The `format` tab has no capability gate: every format shows it, between `rules` and `settings`. A missing, repeated, unknown or unavailable `?tab=` renders the overview; an old id from `LEAGUE_ADMIN_TAB_ALIASES` (`schedule`) opens its tab.
- Back-links into this page name their tab and go there: the draft control page ("Back to league admin: Draft", `?tab=draft`, also its legacy-pool "Manage" link and the draft room's "Go to league admin: Draft"), and a phase page ("← Back to <league>: Phases", `?tab=phases`). Build them with `leagueAdminHref(id, tab)`, never a bare `/admin/leagues/${id}`.
- **Delete hint** (Danger tab, site admins). A league delete **moves the league to the trash** (`DELETE /api/seasons/[id]`, [League recycle bin](./season.md#league-recycle-bin)); the superadmin can restore it for 90 days (`LEAGUE_TRASH_RETENTION_DAYS`) and after that it is removed for good. Nothing blocks the delete any more, so the hint no longer lists blockers (there is no `SEASON_HAS_DEPENDENTS` answer). It states, in order: the intro with the retention window; a folded list ("Show the list (12 groups)") of what the trash keeps a full copy of (participants, league groups, format rules and the draft pool list, phases with their groups and rounds, every match with its games and stats, draft pools, teams, evolution records, token records, Redraft records, storylines, and league admins, Discord webhooks, social integrations and wiki notes); that statistics, ratings and win streaks are recalculated without the league (and again on a restore); that cast sessions, agent suggestions and teams outside the league lose the link and get it back on a restore; that the audit log and the draft action log are kept; and that running drafts are paused at the delete and come back paused, and that the league's players, rulesets and point-buy lists cannot be deleted while it is in the trash. The lists come from `src/lib/league-admin/season-delete.ts`, derived from the SQL inventory (`league_trash__inventory()`: 50 owned tables, 4 derived, 2 kept, 7 pointers): `season-delete.test.ts` replays the migrations, reads the last definition of the inventory and pointer functions and fails when one adds, drops or reclassifies a table without that file following. The delete confirm dialog names the trash and the window (`deleteResource.confirm.season`, `{days}`), and its success notice says "moved to the trash".
- A route id that is not a uuid is a 404 before any read (`isValidUuid`), like the draft control page's `gateDraftAdmin`.
- The server renders, and reads for, the selected tab only (`searchParams` is read as a Promise). Every tab shares the league row and the live access read; the overview needs nothing else. A viewer who is not an admin gets only `AdminGuard` (denial or sign-in redirect) and no tab read runs.
- Site-admin-only parts (Test League, League Admins, phase delete, league delete) are decided from `getLiveAccess()` (the memoised live read the admin layout and `AdminGuard` share), never from the up-to-5-minute-old session copy. Writes stay guarded by their routes.
- Header on every tab: the test badge and `LeagueStatusControl` (status buttons, 44 px tall below `sm`, `aria-pressed`), in a wrapping row below the title rather than `PageContainer`'s non-wrapping `action` slot, so nothing widens the page at 375 px. A custom league without an attached format (and not yet active) gets the optional `blocked` prop: the **Active** button is disabled and the reason ("Attach a format first...", namespace `format-studio/attach`, `status.blockedNoFormat`) is printed under the control and tied to the button with `aria-describedby`. The page makes one extra read for this, `getSeasonFormatSummary`, for custom leagues only; the current status is never blocked, the API and the database trigger still refuse the change, and every other league type renders the control as before. Every other page's `PageContainer` `action` slot wraps below the title on narrow screens for the same reason (the league detail page keeps its own row).
- Tab strip: a `<nav>` landmark (`tabs.label`) of `Link`s with `aria-current="page"` on the active tab, which also `aria-controls` the panel region (`#league-admin-panel`, labelled by the active tab). It scrolls sideways inside itself on a phone (`HubTabStripScroll` keeps the active tab in view), labels have no fixed width (German runs longer), tabs are 44 px tall below `sm`, theme tokens only, and the pending dot pulses only under `prefers-reduced-motion: no-preference`.
- Settings controls sit in plain (non-collapsible) sections and follow their server prop after a save (`useServerSyncedState` + `router.refresh()`), so a remount never shows a stale value. `EditableDescription` keeps unsaved text in the tab's sessionStorage (`src/components/shared/description-draft.ts`): a tab switch, collapse or reload no longer loses it, and the next mount offers it back (**Resume editing** / **Discard draft**); **Edit** opens an offered draft too, so its first keystroke never overwrites it; Save and Cancel drop it. A browser that refuses to store the draft (private mode, blocked or full storage) gets a short notice in the editor and a `console.warn`. These buttons are 44 px tall below `sm`.
- **Other unsaved forms and tab switches.** A tab switch is a navigation: the open panel's forms unmount. Only the description keeps a draft. Every other form opts into a guard: while it holds unsaved input it marks its root `data-unsaved="true"` (`unsavedMarker(dirty)` from `src/lib/league-admin/unsaved.ts`) and drops the marker once the input is saved or discarded. While any marked element is inside the panel region (`#league-admin-panel`), `UnsavedTabGuard` (mounted by the tab strip) asks with the browser's confirm dialog before a tab switch (`tabs.unsavedConfirm`, en + de; declining keeps the tab and its input), and the browser asks before a reload or close. A click on the open tab, or one that opens a new tab or window, is never interrupted. ### League settings, phase and tournament pages
- **League details** (Settings tab, first section; `LeagueSettingsForm`) edits name, league type, battle ruleset and the two dates through `PATCH /api/seasons/[id]`, sending only the changed keys (`buildLeagueSettingsPatch`). The ruleset select is a read-only value once the league has started and has a ruleset (`isRulesetPinLocked`, the server's own test; a hint says to use the pin card). The Overview tab's dates fact links here ("Edit dates"). The description stays on the Overview tab (`EditableDescription`); theme and content language stay in their own Settings sections, so no field has two editors. The league type is disabled with a hint once the league has started or for point-buy leagues, mirroring the server guards (`formatChangeLock`); a point-buy league shows its automatic battle ruleset and never sends `ruleset_id` or `format_type`. The date order is checked in the form and again by the server (`SEASON_DATES_INVALID`). After a save the form stays mounted: the refreshed stored values become its baseline (`adoptStoredLeagueSettings`), so the "saved" notice stays and input typed in the meantime is kept. Rules and error codes: [Season, League settings](./season.md#league-settings-patch-apiseasonsid).
- **New phase** (Phases tab, `PhaseTimeline`): a **Position** control places the phase at the end (default), before or after an existing phase and sends `insert_at` only when it is not a plain append; options in front of a started phase are disabled, as the server would answer `PHASE_INSERT_LOCKED`. A duplicate name (`PHASE_NAME_TAKEN`) or a refused position is shown once, by the phase form.
- **Phase page** (`/admin/leagues/[id]/phases/[phaseId]`): a **completed** phase shows its settings form locked (a notice says so) and a **Reopen** button next to Archive/Delete; reopening asks first and states the consequences (the status goes back to `active`, results and standings stay, completing it again announces the completion again, players already advanced stay in the next phase). It is `PATCH` with `{ status: 'active' }` on the phase or tournament, the same endpoint "Mark completed" uses; no other row is written. Best-of pickers offer 1, 3, ... 15 (odd only; a stored legacy even value stays listed so editing never silently changes it); clearing all best-of overrides now saves. The groups panel offers 2 to 26 groups (the API cap), and drawing groups again over existing ones asks for confirmation first (it deletes the phase's groups and recreates them from the seeds; rounds and matches are not touched).
- **Standalone tournament page** (`/admin/tournaments/[id]/rounds`): a **Settings** section comes first (name, ruleset, best-of and overrides, doubles, bracket type, team visibility, grand-final reset), saved through `PATCH /api/tournaments/[id]` with only the changed keys (`buildTournamentPatch`). Once the tournament has started (status not `upcoming`, or any round) bracket type, ruleset and doubles are disabled and the server refuses a change with `tournament_bracket_locked` / `tournament_ruleset_locked` / `tournament_doubles_locked`; name, best-of, overrides, visibility and the reset toggle stay editable at any status. Details: [Tournament](./tournament.md#standalone-tournament-settings).

### League trash (`/admin/leagues/trash`)
Superadmin only (`SuperadminGuard`; the page reads no trash data until the viewer is known to be the superadmin; the Leagues list links to it for the superadmin). It lists the leagues in the trash: name, format, who deleted it and when, the date until which it can be restored, the row counts (from the trash row, never from the captured data), and badges for **rebuild pending** and **schema changed since delete** (the migration version stored at delete time differs from the current one).
- **Restore** asks first (`ConfirmDialog`), then `POST /api/admin/league-trash/[id]/restore`. The league leaves the table at once and its outcome stays in a notice until dismissed: the warnings of the restore (references cleared because their parent is gone, replay links released, columns ignored since the schema changed), the number of queue drafts that came back **paused** (an admin resumes them from the league's Draft tab), and the rebuild warning, if any.
- **Pending rebuilds.** A delete or a restore that could not finish rebuilding the derived data (aggregates, ratings, streaks, EPB state) leaves a pending marker, shown in a list above the table with a **Run rebuild** action (`POST /api/admin/league-trash/[id]/rebuild`). A trashed league whose delete rebuild is still pending has a disabled Restore (the route would answer 409 `LEAGUE_TRASH_REBUILD_PENDING`: its statistics would be counted twice), and the expiry cron skips it.
- Copy: `league-admin` namespace `trash.*`; the rest from `ui` and `shell`. Below `xl` each row is a card with labelled fields, so Restore is never off-screen on a phone; from `xl` it is the table.

### League groups
A league may split its trainers into groups (design: one round robin, one table and one draft per group; schema and draft engine: [Draft Room, League groups](./draft-room.md#overview)). Leagues without groups behave exactly as before.
- **Editor** (Participants tab, `src/components/league/groups/LeagueGroupsEditor.tsx`, a client component; its markup is `LeagueGroupsEditorView`). It loads `GET /api/seasons/[id]/groups` (league admins only: the groups with their members and a `locked` flag per group, the roster in seed order as `{ id, name, seed }`, `replaceLocked`, and `scheduleLocked`: a phase of the league has a round) and writes through (`editor-requests.ts`: the requests and how each answer maps; after a rename or a refusal the editor re-reads its data, so a lock that arrived meanwhile shows at once):
  - `PUT /api/seasons/[id]/groups` — `{ mode: 'serpentine', group_count }` splits by seed (snake order: the seeds run through the groups in order, then back in reverse, so two groups get 1 → A, 2 → B, 3 → B, 4 → A; seeds from the league's first phase, unseeded trainers after them by name; existing groups keep their names by position, new ones take the next `Group X` no kept group uses, so a group renamed to "Group C" never collides; every group needs two trainers, else `422 SEASON_GROUPS_TOO_MANY`), `{ mode: 'manual', groups: [{ name, player_ids }] }` sets them as given (every participant exactly once: `422 SEASON_GROUPS_INCOMPLETE` / `SEASON_GROUP_PLAYER_NOT_FOUND`; two trainers per group: `422 SEASON_GROUP_TOO_SMALL`), `{ mode: 'clear' }` removes every group (behind a confirm dialog). One transaction (`season_groups_replace`, which checks the same rules again: every participant in exactly one group, two per group); refused once a phase of the league has a round (`409 SEASON_GROUPS_SCHEDULED`), while any group has a live draft pool or drafted lines (`409 SEASON_GROUP_LOCKED`; a draft that has not started, or was cancelled, can be deleted in its draft panel, which frees the group), or when a removed group is still used (`409 SEASON_GROUP_IN_USE`). Audited as `season.groups.replace` (before/after groups and members).
  - `PATCH /api/seasons/[id]/groups/[groupId]` — rename (`{ name }`, 1–60 characters; allowed at any time, also while the group drafts and after the first round). `404 SEASON_GROUP_NOT_FOUND` for a group of another league, `409 SEASON_GROUP_NAME_TAKEN` for a name another group of the league has, ignoring case and blanks (`uq_season_groups_name_ci`), `422 INVALID_CONFIG {field: name}` when the table's length check refuses it. Audited as `season.group.rename`.
